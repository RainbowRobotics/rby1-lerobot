# RB10 Meta Quest Teleoperation

Meta Quest 컨트롤러로 RB10을 조작하고 LeRobot 데이터셋을 수집하기 위한 플러그인입니다.

## Network (예시)

| Device     | IP              | Port               |
| ---------- | --------------- | ------------------ |
| RB10       | `192.168.0.210` | TCP `5000`, `5001` |
| Control PC | `192.168.0.245` | UDP `5005`         |
| Meta Quest | `192.168.0.206` | UDP `6000`         |

## Controls

* **A 버튼**: VR 제어 arm + 로봇을 **고정된 초기 자세로 이동** (5초 보간) +
  **오퍼레이터 기준 좌표계를 현재 HMD 자세로 재설정**.
  이동이 끝날 때까지 Grip은 무시됩니다.
* **Grip 누름**: 그 순간의 컨트롤러 자세를 기준(앵커)으로 잡고 추종 시작
* **Grip 유지**: 앵커 이후의 **손 이동량을 1:1로** EE 위치에 반영.
  **손 회전량은 같은 축으로 `orientation_scale` 배(기본 `1.0`)만큼 반영**됩니다.
  별도의 각도 제한은 없습니다 — 손 회전 델타 자체가 최대 180°이므로
  명령 회전은 `orientation_scale × 180°` 를 넘을 수 없습니다.
  `--teleop.orientation_scale=0.0` 이면 예전처럼 자세가 완전히 고정됩니다.
* **Grip 해제**: 로봇 정지 + 앵커 폐기
* **B 버튼**: VR 제어 종료 (A를 다시 눌러야 함)
* **Trigger**: 그리퍼 제어

실행 후 **A 버튼을 눌러 초기 자세로 보낸 뒤, Grip을 눌러야** 로봇이 움직입니다.

> **A 이동 중에 Grip을 계속 쥐고 있었다면, 놓았다가 다시 눌러야 합니다.**
> 앵커는 Grip의 rising edge에서 잡히므로, 쥔 채로 있으면 추종이 시작되지
> 않습니다. 이는 초기 자세 도착 즉시 로봇이 움직여버리는 것을 막기 위한
> 의도된 동작입니다.

### 클러치 방식

손 위치가 곧 로봇 위치인 절대 매핑이 아니라, **Grip을 누른 시점부터의
이동량만** 반영합니다. 따라서 팔이 불편한 자세가 되면 Grip을 놓고 손을 편한
위치로 되돌린 뒤 다시 누르면 됩니다. 로봇은 그 사이 움직이지 않습니다.

이동량은 **A 버튼을 누른 순간의 HMD 자세**로 정해지는 오퍼레이터 좌표계 기준으로
측정되며, 다음 A 를 누를 때까지 고정됩니다. 조작 중은 물론 **스트로크 사이에** 고개를
돌리거나 몸 방향을 바꿔도 손↔로봇 축 대응이 달라지지 않습니다.

작업 자세를 바꿔 앉았거나 방향 감각이 어긋났다면 **A 를 다시 눌러 좌표계를 재설정**하면
됩니다. B 로 disarm 하면 좌표계도 함께 버려지므로, 다시 A 를 눌러야 합니다.

### 작업자 ↔ 로봇 축 대응

작업자 좌표계는 오른손 좌표계로, **정면 = `+X`, 왼쪽 = `+Y`, 위 = `+Z`** 입니다.
현재 대응은 다음과 같습니다 (EE 열은 `VR_HOME_POSE` 자세 기준):

| 작업자 손 이동 | 로봇 base | 홈 자세 EE |
|---|---|---|
| `+X` (정면) | `-X` | `-Y` (그리퍼가 향하는 방향) |
| `+Y` (왼쪽) | `-Y` | `+X` |
| `+Z` (위) | `+Z` | `+Z` |

즉 **손을 앞으로 밀면 그리퍼가 향하는 방향으로** 로봇이 갑니다(EE `-Y` = approach 축
`-fk[:3, 1]`). 보정 상수 `frame_transforms.R_OPERATOR_TO_BASE` 는 **`Rz(-90°)`** 이고,
이는 홈 자세 EE 가 base 를 `-90°` 요(yaw)한 자세이기 때문입니다. 단위행렬일 때의
대응은 정면→base `-Y`, 왼쪽→base `+X` 입니다.

이 상수는 **base 고정 회전**이라 EE 열은 앵커 자세가 홈 자세와 같을 때만 성립합니다
(손목을 따라 돌지 않음). **홈 자세의 orientation 을 바꾸면 이 상수도 반드시 같이 다시
잡아야 합니다** — `test_operator_to_base_maps_operator_axes_onto_the_home_ee_axes` 가
홈 자세 FK 를 직접 읽어 두 상수의 정합성을 검사합니다. 작업자 스테이션 위치가 바뀌어도
다시 잡되, **반드시 행렬식 +1 인 정상 회전**이어야 합니다.

> **이 표는 회전축에도 그대로 적용됩니다.** `R_OPERATOR_TO_BASE` 가 행렬식 +1 인
> 정상 회전이므로 작업자 프레임의 한 축은 그것이 이동 방향이든 회전축이든 같은
> base 축으로 갑니다. 즉 손을 작업자 `+X` 축 둘레로 돌리면 툴은 base `-X` 축
> 둘레로 돕니다. 회전 델타는 similarity(`R X Rᵀ`)로 옮겨지고, 적용되는 각도는
> 손 회전각 × `orientation_scale` 입니다.
> (`test_rotation_delta_axis_map_matches_the_translation_axis_map`)

> **핸디드니스는 이미 처리돼 있습니다.** `T_conv` 의 행렬식이 `-1` 이라
> `quest_pose_to_rb` 가 Unity 의 왼손 좌표계를 오른손 좌표계로 변환합니다
> (Unity `+X`→RB `-Y`, `+Y`→RB `+Z`, `+Z`→RB `+X`).
> 관측된 작업자→플랜지 대응의 행렬식도 `+1` 이라 거울상이 아닙니다.

### 회전 방향

**이 항목은 실기에서 아직 검증되지 않았습니다.** 위 축 대응표는 `실기에서 측정한
대응`이지만, 측정된 것은 **이동**뿐입니다. 자세 추종은 이 저장소에서 처음 켜지는
기능이라 회전 방향을 실물로 확인한 적이 없습니다.

수치상으로는 맞습니다. `T_conv` 의 행렬식이 `-1` 이라 similarity 변환이 회전
유사벡터의 부호를 뒤집는데, 이것이 바로 Unity 왼손 좌표계 → 오른손 좌표계 변환입니다.
그래서 Quest `+X` **이동**은 RB `-Y` 로 가는데 Quest `+X` **회전**은 RB `+Y` 축
회전으로 나옵니다 — 모순이 아니라, 축 이름과 회전 방향이 함께 뒤집혀 물리적으로는
같은 회전이 됩니다.

다만 Quest 앱의 쿼터니언 규약이 가정과 켤레만큼 다르면 **모든 회전이 거울처럼
반대로** 나타납니다. 위험하지는 않지만(관절 스텝 제한이 그대로 걸립니다)
"기능이 고장난 것처럼" 보입니다.

확인 절차: `--teleop.orientation_scale=0.1` 로 실행 → Grip → 손을 앞뒤 축 둘레로
90° 굴리기 → 플랜지가 **같은 방향으로** 도는지 확인.

거울로 나온다면 고칠 곳은 `frame_transforms.controller_rotation_delta` 의 회전
유사벡터 부호 하나입니다. **`R_OPERATOR_TO_BASE` 를 건드리지 마세요** — 그 상수는
행렬식 +1 인 정상 회전이어야 하고(`test_operator_to_base_is_a_proper_rotation`),
회전축 부호 반전은 정상 회전으로 표현할 수 없습니다.

### 초기 자세

`constants.VR_HOME_POSE_DEG` = `(-172.5253, -3.3101, 141.8867, 41.4234, 277.4747, 180)` 도.
코드 상수라 CLI로는 바꿀 수 없습니다.

| | 값 |
|---|---|
| EE 위치 | `(-618.6, 110.5, 264.0)` mm — 교시 위치 그대로 (그리퍼 끝단 기준) |
| **EE `x,y` 평면** | **base `x,y` 평면과 완전히 평행 (틀어짐 0)** |
| EE 자세 | base 를 `-90°` 요(yaw)한 형태 (정수 행렬, 오차 5.8e-16) |
| **EE `+Y` 축** | `(1, 0, 0)` — base `+X` 와 정확히 일치 (offset 0) |
| **그리퍼 방향** | `(-1, 0, 0)` — **수평, base `-X` 방향** |

**이 값은 직접교시로 잡은 자세를 스냅한 것입니다.** 2026-09-16 에 제어박스에서
`program_mode == 0` 으로 직접 읽은 값:

```
jnt_ang   = (-172.1388, -3.8135, 141.3375, 43.9742, 278.3751, 182.6252) deg
tcp_pos   = (-475.1793, 109.8054, 268.0233) mm
tcp Euler = (1.4627, 2.9902, -90.2875) deg
```

교시는 **위치**를 정한 것이고 orientation 은 대충 잡힌 상태였습니다 — 제어박스의
`rx`/`ry` 가 곧 EE `x,y` 평면이 base `x,y` 평면에서 틀어진 양인데 합쳐서 `3.21°`,
요(yaw)도 `-90°` 에서 `0.29°` 벗어나 있었습니다. **같은 EE 위치**에서 이 틀어짐을 0 으로,
요를 정확히 `-90°` 로 스냅해 IK 로 다시 푼 결과가 위 값입니다. **관절 변화는 최대
`2.63°`** 입니다. 위치를 기하로 재유도하지 마세요 — 작업자가 팔을 실제로 놓은 위치가
이 숫자에 들어 있습니다.

> **제어박스와 이 모델은 orientation 은 같고 position 이 다릅니다.** 펜던트 값과
> 비교하기 전에 알아두세요. 위 `tcp Euler` 를 `Rz @ Ry @ Rx` 로 풀면
> `get_fk()[:3, :3]` 와 `0.15°` 내로 일치합니다 — 즉 회전행렬은 제어박스의 툴
> 회전 그대로입니다. 위치는 툴 `+Y` 축 방향으로 `143.44 mm` 차이가 납니다. 이
> 모델은 **마지막 링크에 그리퍼가 포함**돼 있어(손목에서 `259.3 mm`, 맨 플랜지는
> `115.9 mm`) `get_fk()` 는 **그리퍼 끝**, `tcp_pos` 는 **플랜지**를 가리킵니다.
> 스냅은 끝단 기준 회전이므로 **끝단은 `0.0002 mm`, 플랜지는 `3.93 mm`** 움직입니다.

> **세 가지가 자세를 고정합니다.** 이 교시 자세는 **손목이 뒤집힌**(j5 = `180°`)
> 브랜치라, 예전 홈 자세(j5 = `0°`)와 **규칙이 다릅니다**.
>
> | 제약 | 의미 |
> |---|---|
> | `j1 + j2 + j3 = 180°` | flange **pitch** |
> | `j0 - j4 = -450°` | flange **yaw** (`-90° mod 360`) |
> | `j5 = 180°` | 손목 뒤집힘 |
>
> 섭동으로 확인했습니다: j1↔j2 를 맞바꾸거나 j0 와 j4 를 **같은 방향**으로 움직이면
> 회전행렬이 `3e-16` 내로 그대로지만, 예전 규칙대로 j0 와 j4 를 **반대 방향**으로
> 움직이면 자세가 틀어집니다. 자세를 다시 잡을 때는 j3 와 j4 를 **마지막에**
> `j3 = 180 - j1 - j2`, `j4 = j0 + 450` 으로 계산하세요.

> **손목보다 j2 를 주시하세요.** j2 는 `141.89°` 로 `RB10E_JOINT_LIMITS_DEG` 의
> `±154°` 리밋에서 `12.11°` 밖에 안 남았고, base `Y` 축으로 툴을 `30°` 돌리면 그중
> `6.8°` 를 씁니다. IKLM 은 리밋에서 clip 하므로 더 요구하는 스트로크는 추종 대신
> 포화됩니다. 손목은 상대적으로 여유가 있습니다 — RB10E 손목은 `j4 = 0/180/360°`
> 에서 특이한데 `277.47°` 는 `360°` 에서 `82.5°`, `180°` 에서 `97.5°` 떨어져
> 있습니다. 손목 여유를 가장 빨리 쓰는 것은 base `Z` 회전 한 방향으로, `-30°` 면
> j4 가 `326.12°`(특이점에서 `33.9°`)까지 갑니다. 뻣뻣하면
> `--teleop.orientation_scale` 을 먼저 낮추세요.
>
> 팔 전체 조건수는 `9.32`, 최소 특이값은 `0.212` 입니다(선형 블록 m 단위).

EE 자세를 base 정렬로 잡은 이유는, 추종 중 EE 자세가 이 **앵커 자세를 기준으로**
회전하기 때문입니다. 초기 자세의 orientation 이 세션 전체의 **기준** orientation 이고,
매 스트로크의 자세는 `앵커 자세 × (손 회전 × orientation_scale)` 입니다.

이동 추종은 `ik_iterations = 5` 기준으로 `100 mm` 명령 시 **첫 틱**에 남는 오차가
base `+X` `0.0095 mm`, `+Y` `0.18 mm`, `+Z` `0.18 mm` 입니다. 회전은 base `X` 가
flange spin 축이라 거의 공짜(`18°` 명령이 한 틱 뒤 `1.4%` 남음)이고, base `Y` 는
`31%`, base `Z` 는 `29%` 남습니다.

> **주의 — 그리퍼 방향은 `-fk[:3, 1]` 입니다 (Z열 아님).**
> `rb10e_kinematics.py` 는 모든 관절축을 프레임의 **Y열**에 두고, 툴 변환이 항등이라
> 이 관례가 `get_fk()` 에 그대로 나옵니다. 흔한 "Z 가 플랜지 밖으로" 관례를 가정하면
> 90° 어긋난 자세를 고르게 됩니다.

## Teleoperation

```bash
lerobot-teleoperate \
  --robot.type=rb10 \
  --robot.ip=192.168.0.210 \
  --teleop.type=rb_vr \
  --teleop.local_ip=192.168.0.245 \
  --teleop.meta_quest_ip=192.168.0.206 \
  --teleop.send_handshake=true \
  --fps=30
```

자세 추종 비율은 `--teleop.orientation_scale` 로 조절합니다.

| 값 | 동작 |
|---|---|
| `0.0` | EE 자세를 앵커 자세로 완전히 고정 (이 기능 도입 전과 동일) |
| `0.3` | 손을 90° 돌리면 툴은 27° |
| `1.0` | **기본값.** 1:1, 위치 매핑과 동일 |

> **큰 회전의 한계.** 손 회전 약 **110°까지는 정확히 추종**합니다. 그 이상 최악의
> 축으로 돌리면 팔꿈치(joint 2)가 완전히 펴지면서 IK가 명령 자세에서 몇 도 벗어난
> 곳에 정착합니다 (측정값: 130°에서 5.2°, 150°에서 1.9° 오차). 반복 횟수를 늘리면
> 오히려 나빠지는데, 이는 반복 부족이 아니라 **특이 자세**의 특징입니다.
> **위치는 그대로 정확**해서(0.005 mm 이내) `IK_RESIDUAL_LIMIT_MM` 검사가 잡지
> 못합니다. 각도 클램프를 없앤 대가이며, 발산하지는 않습니다.

**실기에서 처음 돌릴 때는 `--teleop.orientation_scale=0.1` 로 시작하세요.**
Grip 을 쥐고 손을 앞뒤 축 둘레로 90° 정도 굴려, 플랜지가 **눈으로 보기에 같은
방향으로** 도는지 확인합니다. 반대로 돌면 멈추고 아래 "회전 방향" 항목을 보세요.

팔과 + 그리퍼 사용:

```bash
lerobot-teleoperate \
  --robot.type=rb10 \
  --robot.ip=192.168.0.210 \
  --robot.gripper_type=rby1_dynamixel \
  --teleop.type=rb_vr \
  --teleop.local_ip=192.168.0.245 \
  --teleop.meta_quest_ip=192.168.0.206 \
  --teleop.send_handshake=true \
  --teleop.use_gripper=true \
  --fps=30
```



## Record Dataset

```bash
lerobot-record \
  --robot.type=rb10 \
  --robot.ip=192.168.0.210 \
  --robot.gripper_type=rby1_dynamixel \
  --teleop.type=rb_vr \
  --teleop.local_ip=192.168.0.124 \
  --teleop.meta_quest_ip=192.168.0.16 \
  --teleop.send_handshake=true \
  --teleop.use_gripper=true \
  --dataset.repo_id=rainbowrobotics/rb10_vr_demo \
  --dataset.num_episodes=20 \
  --dataset.single_task="Control the RB10 arm and gripper using Meta Quest VR." \
  --dataset.push_to_hub=false \
  --dataset.fps=30
```


`dataset.repo_id`, `dataset.num_episodes`, `dataset.single_task`는 수집 작업에 맞게 변경합니다.
